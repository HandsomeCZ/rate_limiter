# 面试准备文档

## 项目介绍模板

### 1. 一句话介绍
> 我实现了一个双引擎风控限流网关，基于Reactor网络框架，支持10w QPS，P99延迟<2ms。

### 2. 架构分层
```
网络层（Reactor模式）
  ├── EventLoop（One Loop Per Thread）
  ├── Channel（fd事件封装）
  ├── Poller（epoll/select）
  ├── TcpServer（连接管理）
  └── Buffer（双缓冲区）

应用层（双引擎架构）
  ├── 风控引擎：特征提取 → 规则匹配 → 风险评分 → 决策分发
  ├── 限流引擎：滑动窗口 + Redis + 分片
  └── 监控体系：EventBus → Metrics → Prometheus
```

### 3. 核心亮点
1. **双引擎串联**：先风控评分（ALLOW/LIMIT/CHALLENGE/REJECT），再限流检查
2. **性能优化**：Reactor + 非阻塞IO + 双Buffer + 黑白名单快速路径
3. **高可用**：Redis熔断 + fail-open降级 + 热加载规则
4. **监控体系**：拦截率、规则命中、误杀率、Prometheus导出

## 高频问题回答

### Q1: 评分机制怎么算的？
**规则触发分 + 特征贡献分**
- 规则触发：判断请求特征是否满足条件（如qps>50），满足则获得基础分×权重
- 特征贡献：特征值×权重（如ip_risk=85 × 0.3 = 25.5分）
- 两者叠加：定性（是否异常）+ 定量（异常程度）

### Q2: Redis挂了怎么降级？
**三层降级**：
1. 连接层：连接失败计数+熔断，达到阈值放弃请求
2. 风控层：特征提取返回默认安全值，评分降低
3. 限流层：fail-open策略默认放行，记录监控

### Q3: 新规则上线如何验证不误杀？
**四步验证**：
1. 监控拦截率：看拦截数变化
2. 规则效果评估：ruleHitCount=0说明未生效，过多说明太严格
3. 故障排查：RiskEvent日志查触发规则、评分、决策原因
4. 数据回流：优化模型、分析攻击模式、调整策略

### Q4: 1000条规则怎么优化？
**双重策略**：
1. 重复请求：本地LRU缓存+定时过期
2. 新请求：维度索引（哈希表管理，key=规则名，value=相关规则数组）
3. 超大规则量：决策树（logn复杂度，可提前终止）

### Q5: EventBus怎么工作的？
**异步事件上报**：
1. 主链路同步返回后，异步发布RiskEvent到有界队列（10000容量）
2. 后台线程消费事件，更新Metrics统计
3. 队列满则静默丢弃（背压保护，不阻塞主链路）
4. 支持优雅退出（stop + join）

### Q6: 如何支持更高QPS？
**优化方向**：
1. 本地计数+Redis兜底：本地维护计数器，达阈值时向Redis确认
2. 热点特征缓存：高频特征本地缓存，减少重复计算
3. 规则索引优化：维度索引+LRU缓存
4. 批量上报：异步批量同步到Redis，减少网络往返

## 面试技巧

### 主动引导
- "我实现了完整的Reactor网络框架" → 引导问网络编程
- "我有完整的监控体系" → 引导问生产意识
- "我采用双引擎架构" → 引导问架构设计

### 诚实表达
- 被问压测："10w QPS是理论值，参考muduo。实际压测计划用wrk。"
- 被问EventBus："代码已写好，已集成到main.cpp。"
- 被问分布式："当前是单机版，多网关需配置中心同步规则。"

### 强调思考
- 不说"我用了XX技术"，说"我为什么选XX技术"
- 不说"我实现了XX功能"，说"我解决了XX问题"
- 强调trade-off（权衡），如"用最终一致性换性能"
